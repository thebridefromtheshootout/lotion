5. ✅ codeblock allows entering h1/h2/h3 inside it. this is wrong. do an analysis of semantically invalid insertions that are allowed then plan on extending the cmdfilter infra to filter these invalid combinations out.

   Analysis (semantically invalid insertion sites for block-level markdown):
   • Fenced code block (``` / ~~~): contents render verbatim — any markdown
     produces literal text instead of structure (the user's reported case).
   • Inline code span (`...`): same issue, in-line.
   • Graph fence (lotion-graph): DOT source — markdown not interpreted.
   • Processor fence (lotion-proc): processor input — markdown not interpreted.
   • Table cell: block-level markdown breaks the row/pipe layout.
   These four contexts are unified by the new predicate.

   Implementation:
   • New CmdFilter methods:
       cursorNotInCode()           — strict opposite of cursorInCode
       cursorAllowsBlockMarkdown() — the union check above
   • Applied cursorAllowsBlockMarkdown() to every block-style slash command:
       blockInserts (h1, h2, h3, todo, divider, quote, math, mermaid,
                     frontmatter), callout (toggle-h1/h2/h3, toggle, callout),
       codeBlock, toc, footnote, table /table, graph /graph, image /image,
       resource /resource, secretbox /secretbox, /section
   • cursorNotInCode() applied to /inline-math (table-friendly, not
     legal inside code).
   • Lists / db-entry contexts unaffected — block markdown still nests
     correctly there.
   • 9 new unit tests in src/__tests__/cmdFilter.test.ts covering the
     positive + negative cases for the new predicates.

   Out of scope (kept their existing behavior):
   • /emoji, /date, /today, /smart-paste — these emit plain text that's
     valid inside code (a date string in a comment, an emoji literal, etc.).
   • /copy (cursorInCode) — only meaningful inside code.
   • /lock, /unlock (cursorInSecretbox), /render (cursorInGraph),
     table-edit subcommands (cursorInTable) — already gated correctly.
