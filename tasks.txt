4. ✅ WSL clipboard image paste still flaky. Replace the powershell.exe/wslpath
   shell-out path in src/media/clipboard.ts with VS Code's native
   `vscode.languages.registerDocumentPasteEditProvider` (added in 1.84+).

   Why this fixes WSL specifically — the current pipeline shells out to
   powershell.exe from inside WSL via wslpath, with four failure modes:
     a. powershell.exe not on PATH (fresh distro, PATH missing
        /mnt/c/Windows/System32/WindowsPowerShell/v1.0).
     b. wslpath missing on older / non-Microsoft distros.
     c. 200–800 ms cold-start tax on every paste for `powershell.exe -NoProfile`.
     d. WSL2 9P filesystem races: powershell-side write → \\wsl$\… can race
        WSL's filesystem watcher and produce a 0-byte file that hits the
        "failed to save" branch.

   The paste provider runs in VS Code's renderer (always on the Windows host
   under WSL Remote) and ships the image bytes to the extension host through
   the same RPC channel imageDrop.ts already uses. No powershell, no wslpath,
   no xclip.

   API shape (mirrors registerDocumentDropEditProvider in imageDrop.ts):

     hostEditor.registerDocumentPasteEditProvider(
       { language: "markdown" },
       {
         async provideDocumentPasteEdits(document, ranges, dataTransfer, ctx, token) {
           const item = dataTransfer.get("image/png") ?? dataTransfer.get("image/jpeg");
           if (!item) return undefined;
           const file = await item.asFile();
           if (!file) return undefined;
           const bytes = await file.data();
           // write bytes to .rsrc/<name>.png, return a DocumentPasteEdit
           // whose snippet is `<img src=".rsrc/<name>.png" alt="<name>">`
         },
       },
       {
         providedPasteEditKinds: ["text.markdown"],
         pasteMimeTypes: ["image/png", "image/jpeg", "image/gif", "image/webp"],
       },
     );

   Migration path:
     a. Add registerDocumentPasteEditProvider() to src/hostEditor/HostingEditor.ts
        and re-export DocumentPasteEdit from src/hostEditor/EditorTypes.ts.
     b. New file src/media/imagePaste.ts mirroring imageDrop.ts shape, handling
        image/* mime types only, writing to .rsrc/, returning a DocumentPasteEdit.
     c. Wire it in src/extension.ts next to createImageDropProvider().
     d. Keep src/media/clipboard.ts as a fallback for now. In handleSmartPaste
        (src/editor/smartPaste.ts), gate the existing image branch so it only
        runs when the paste provider didn't fire (e.g. older VS Code). After a
        release of stable use, delete the WSL/PowerShell branch entirely.

   Doesn't fix on its own:
     - Smart-paste link-unfurling (the <a href> building in smartPaste.ts).
       Paste providers fire instead of editor.action.clipboardPasteAction, so
       eventually one provider should handle both cases (text/uri-list →
       unfurl link, image/png → save image). Returning undefined from the
       provider falls through to default paste behavior, which lets the
       existing handleSmartPaste keep handling the text path while we migrate.
     - Multi-mime ranking — copying from a browser sometimes gives both
       image/png AND text/html. Set explicit pasteMimeTypes priority so
       image/* wins, otherwise VS Code may dispatch to a different provider.

   Gotcha: handleSmartPaste calls editor.action.clipboardPasteAction for
   fallthrough. Once the provider is live, that built-in command will trigger
   the new paste provider too — risk of loop. Gate handleSmartPaste so it
   doesn't call clipboardPasteAction when an image format is on the clipboard
   (let the provider handle it). Drop provider has the same shape and works
   because drop and paste are separate trigger paths.

14. Database filter bar UX audit (NOT the filter tree — that part works).
    Write a notes doc next to CODE_QUALITY.md analysing the shortcomings of
    the filter bar: column select → operator select → value cell → Create
    Filter Tile button.

    Specific things worth auditing:
    - Operator menu is a flat list of 20 ops regardless of column type. A
      regex op on a checkbox column makes no sense; "between" on a select
      column makes no sense; "has_any" on a text column makes no sense.
      Should be filtered to ops valid for the selected column's type.
    - The operator labels mix symbols and words inconsistently
      ("== (equals)", ">", "contains", "isempty"). Pick one register.
    - "between" requires two values but the value cell accepts a single
      free-form string. There's no UI affordance for the second bound.
    - "in" / "!in" accept a comma-separated string but the user has no
      hint about that format and no chip UI to build the list.
    - "matches_regex" is free-form text with no validation feedback when
      the regex is malformed.
    - Date columns get a single date input, but ops like "between" need
      two dates and the input falls back to plain text.
    - Multi-select value picker (checkbox list) has no search; with 30+
      options it becomes unusable.
    - The value cell doesn't react to invalid input — Enter just flashes
      the bar.
    - "Create Filter Tile" is a verbose noun-phrase label; could be
      Enter-only or a tighter "Add" button.
    - The bar doesn't remember the last selected column/op when the user
      adds a tile — small UX papercut.
    - Coordinates and url column types fall through to plain text.

    Deliverable: src/../FILTER_BAR_AUDIT.md (or DB_FILTER_BAR.md) with
    findings in the same table-style as CODE_QUALITY.md, with file:line
    citations.

15. Make Lotion databases actually useful for real work.
    Write a forward-looking doc (DATABASE_ROADMAP.md or similar) next to
    CODE_QUALITY.md. Premise: Lotion's databases today are a playground —
    views, filters, sort exist; what's missing is what Notion users live
    on day-to-day. Plain-markdown-on-disk + a real database engine is
    the unique pitch, but only if the database engine is real.

    Topics to cover, with concrete proposals for each:
    - Formulas (computed columns). E.g. `=concat(first, " ", last)` or
      `=sum(price * qty)` or `=daysSince(due)`. Where would the formula
      live in the schema fence? How are circular refs detected?
    - Relations across databases. `relation:other-db` column type whose
      value is a link to another DB's entry. Bidirectional reverse-link
      surfacing.
    - Rollups. Aggregations across a relation — count, sum, avg, min, max,
      concat, latest, earliest. Notion calls these "rollup properties."
    - Templates for new entries (per-database). When clicking "New Entry"
      offer N templates with pre-filled property values + body skeletons.
    - Form view / quick-entry. A compact form (one entry per submit) for
      data capture, separate from the table editor.
    - Better imports: today CSV → DB and table → DB. Could add JSON,
      ndjson, markdown frontmatter scan ("turn this folder of pages into
      a DB").
    - Better exports: CSV out exists. Add markdown table out, JSON out,
      and a "publish DB as static HTML" path.
    - Cross-database joins / lookups in views (not just within one DB).
    - Property history / audit trail (who/when changed what — works since
      data is git-tracked).

    For each, identify the file(s) that'd need changes (likely
    src/database/dbCommands.ts, src/database/databaseTypes.ts in
    contracts/, the dbWebview, FormatCell, schema fence parser). Order
    by impact × effort.
